REA Studio V1.2.0 (1.2.0) makes IDA Pro a full analysis partner, keeps long analysis sessions alive, and guides each reverse engineering stage.

- **IDA Pro, headless and persistent.** `Install-IDA-Bridge.ps1` sets up pinned ida-pro-mcp (commit c133c385) with your licensed IDA's idalib in an app-local environment. REA's IDA provider can then run without the IDA window, and the new IDA bridge gives the analysis panel, coding agent and MCP clients the live IDA tools: Hex-Rays pseudocode, disassembly, xrefs, callees, call graphs, basic blocks, types and searches. Renames, comments and types are saved in a private IDB per binary, so understanding accumulates across sessions. The original file is never written. Patching, Python evaluation and debugger tools are never exposed. The earlier attached (GUI) IDA setup keeps working.
- **Guided workflow.** The Reverse engineering panel shows each stage and the next required action or missing configuration, based on actual connections and saved results, and points to the control that completes it.
- **Reliable analysis sessions.** A slow REA/Ghidra call no longer destroys the open target and Evidence IDs; Disconnect and Close respond immediately; Ghidra/Java, idalib and command process trees are owned by Windows Job Objects so they are not orphaned.
- **Stronger agent.** Configurable step limit (default 40), `edit`/`append`/`note` actions, context compaction that keeps evidence references, oversized results that point to their retained pages, truncation and provider errors reported honestly with retries, and a corrected REA tool set including xrefs, batch decompilation and annotations.
- **Trustworthy oracles.** Suites run only after you approve their exact SHA-256. The agent's file actions cannot alter the dossier during implementation, and neither they nor MCP file tools can approve a suite; shell commands run with your permissions and are not a security boundary. `argv` cases compare output byte for byte and missing programs fail.
- **Safer coding tasks.** Risky agent commands (recursive deletes, `git reset --hard`, force pushes, system changes, download-and-execute, encoded PowerShell, elevation) wait for your approval. Approval is a pattern check on the command text, not a sandbox, and each answer is bound to the command you reviewed. Each task records the files it wrote with their previous content, so you can view diffs and revert them; files you changed afterwards are protected unless you force it. Follow-up tasks build on an earlier task's answer and changes.
- **Terminal and Git.** Terminal output streams live, Stop ends the whole process tree, and `cd` carries over between commands inside the project. PowerShell 7 is used when installed. Trailing comments and stale exit codes no longer break commands, and long output keeps its end. The Changes panel lists files with line counts and can stage, unstage, discard and commit (repository hooks do not run: `core.hooksPath` points at the null device). CRLF files and BOMs are preserved on save; files with mixed line endings are saved as LF (the editor says so). Saves replace the file, so hard links are not preserved.
- **Safety.** Opening an untrusted folder no longer lets its Git config run programs; model-chosen UNC paths are rejected before the file system is touched.

Extract the complete `REA-Studio-1.2.0-x64.zip` and run `REAStudio.exe`. Keep one current installation, archive earlier copies, and point your shortcut at the current executable. Close the app before moving or replacing its files. Optional tool environments and MCP registrations may contain absolute paths and must be reconfigured if their installation moves.

The IDA integration requires a licensed IDA Pro 9.x with idalib and Python 3.11+. Successful decompilation does not establish original source recovery or complete behavioural equivalence.
